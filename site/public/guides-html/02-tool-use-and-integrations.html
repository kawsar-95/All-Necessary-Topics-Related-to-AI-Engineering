Tool use & integrations (incl. MCP)

An LLM is just a text generator until you give it tools: a way to call your API, run code, query a database, or read a file. Tool design is the difference between a chatbot demo and a production system. The single highest-leverage decision is the quality of your tool descriptions.

Tool/function schema design

A tool is a JSON Schema (or a Pydantic / Zod object) plus a short description that the LLM reads before deciding to call it. Anthropic and OpenAI both document the same rules:[10][11]

  • Name: verb_noun. search_documents, not docs. Names appear in the model's context window — they're a contract.
  • Description: one sentence on what it does, one on when to use it, and one on what it returns. Treat it like a function docstring the model must read.
  • Parameters: explicit types, enums for closed sets, descriptions for every non-obvious field. Avoid any; the model hallucinates less when the schema is tight.
  • Returns: document the shape. If the tool can fail, return an error field, not a 500.
# Tool schema (Anthropic style)
tools=[{
  "name": "search_documents",
  "description": "Search the company wiki for documents matching a query. Use when the user asks about internal policy, prior projects, or people. Returns top-5 chunks with source URLs and a relevance field 0–1.",
  "input_schema": {
    "type": "object",
    "properties": {
      "query": {"type": "string", "description": "Natural-language query; 3–8 words works best."},
      "filter": {"type": "string", "enum": ["all","policy","engineering","people"], "description": "Optional filter."}
    },
    "required": ["query"]
  }
}]
Number of tools: more than ~20 tools in a single prompt measurably degrades selection accuracy (the many-tools problem). Split into sub-agents by domain, or use a router.

Parallel tool calling

When the model needs to gather information that doesn't depend on itself (e.g. "look up weather in Tokyo and the exchange rate"), it should issue those calls in one turn, not three. Modern APIs return all parallel results at once; the orchestrator runs them concurrently. This is the single biggest latency win in tool-heavy agents.

Model Context Protocol (MCP)

MCP is an open standard (introduced by Anthropic in late 2024, now adopted by OpenAI, Google, and the major IDE vendors) for connecting models to data and tools.[12] The model is the client; the data/tool provider runs an MCP server. The server exposes three primitives:

  • Tools — functions the model can call (the action surface).
  • Resources — read-only data the client can fetch on demand (files, DB rows, web pages). Model decides to read based on its goal.
  • Prompts — named prompt templates the server offers; the host can list them and let the user invoke by name.
MCP architecture: one host can speak to many servers in parallel, each over stdio, SSE, or streamable HTTP. Servers expose tools (actions), resources (data), and prompts (templates).
MCP আর্কিটেকচার: একটি host একাধিক server-এর সাথে কথা বলে (stdio / SSE / HTTP); প্রতিটি server tools (কর্ম), resources (তথ্য) ও prompts (টেমপ্লেট) প্রকাশ করে।
Why MCP matters: before MCP, every IDE / agent app wrote custom integrations for every data source. Now you write one MCP server (e.g. for Postgres) and every MCP-compatible client — Claude Code, Cursor, VS Code, custom agents — can use it.

Sandboxed code execution

Many agent tasks are easiest to express as code ("compute the average of column X"). Letting the model generate and execute code in a sandbox avoids tool explosion and gives you correctness on arithmetic. The four production options in 2025:

API wrappers as tools

Every internal API becomes a tool: wrap each endpoint with a function that (a) describes its purpose in one sentence, (b) accepts a typed input, (c) returns either the result or an {error, retryable} envelope. The model will route to the right tool if the wrapper is honest about its limits (e.g. "max 100 results, paginate with cursor").

Tool result formatting for LLM consumption

The model re-reads your tool's output as part of its next turn. That output is prompt content. Three rules:[10]

  • Trim ruthlessly. A 10,000-row SQL result will blow your context window. Return the top N, summarise the rest.
  • Format for reading, not for storage. Markdown tables beat JSON arrays for human-shaped reasoning.
  • Include a "what this means" sentence when the result is non-obvious — saves the model a re-derivation.
🛠️Layman's versionplain English, no jargon

A "tool" is just a button the AI is allowed to press. By default, an AI can only chat. Give it a "search Google" button, and now it can search. Give it a "send email" button, and now it can email. Give it 30 buttons, and it can do 30 things. Each button needs a clear label ("search Google for the top 5 results, returns URLs") or the AI will press the wrong one.

The label is everything. Imagine you're giving a new intern 20 buttons and one instruction: "press the right button when I ask you something." You'd write each label super clearly, right? Same with AI tools. A tool called search with no description gets pressed at the wrong time. A tool called search_documents(query, max_results=5) with the description "Search the company wiki for documents matching the user's question. Use when the user asks about internal policy or people" gets pressed at the right time.

Do things in parallel when you can. If the AI needs both "weather in Tokyo" and "USD to JPY rate," it should press both buttons at the same time, not one after the other. Modern AI does this automatically — and it's the single biggest speed win for tool-heavy assistants.

MCP (Model Context Protocol) is the universal plug. Before MCP, every chatbot app wrote its own custom integration for every tool — like Apple chargers, USB-C chargers, micro-USB chargers. MCP says: "all tools speak this one protocol." Now any MCP-compatible chatbot can use any MCP-compatible tool, no glue code. Anthropic released it in late 2024; OpenAI, Google, and every major IDE vendor have adopted it.

Sandboxed code execution = "the AI can run a tiny computer." Sometimes the cleanest way to answer "what's the average of these 1,000 numbers?" is to let the AI write and run Python. But you don't want the AI running Python on your real laptop — so you put that Python in a locked sandbox (E2B, Modal, Daytona, Cloudflare Workers). It can compute, but it can't reach your files, your network, or your data.

The output of a tool is also a prompt. The AI re-reads what the tool returned as part of its next thought. So the output shouldn't be a giant wall of raw JSON; it should be a tidy Markdown table with the key numbers up front and a one-line summary at the bottom. Same way you'd summarise a report for a colleague.

The toolbox analogy: think of the AI as a handyperson. You can hand them a toolbox with 30 tools in it, but if every tool is labelled vaguely ("thingamajig," "whatsit"), they'll pick the wrong one. Label them clearly ("Phillips screwdriver, size 2"), and they pick the right one. MCP is the standard size for tool handles — every toolbox now fits every tool. The summary rule: when the handyperson comes back from the crawl space, they tell you what they found in plain English, not by dumping the entire junk drawer on your kitchen table.
🇧🇩বাংলা ব্যাখ্যাসহজ ভাষায় বিস্তারিত

Tool হলো এমন একটি ফাংশন যা model কল করতে পারে। LLM আগে শুধু text generate করতে পারে; tool যোগ করলে সে আপনার API কল করতে, কোড রান করতে, ডাটাবেস query দিতে বা ফাইল পড়তে পারে। Tool-এর description-এর মানই নির্ধারণ করে চ্যাটবট ডেমো আর প্রোডাকশন সিস্টেমের মধ্যে পার্থক্য।

Schema-এর নকশা: name verb_noun হওয়া উচিত (search_documents, docs নয়); description-এ এক লাইনে কী করে, কখন ব্যবহার করবে ও কী ফেরত দেয় — তিনটিই থাকা উচিত।[10] Parameter-এ explicit type, enum ও description দিন; any এড়িয়ে চলুন। একটি prompt-এ ২০-এর বেশি tool দিলে selection quality ক্ষতিগ্রস্ত হয় — domain অনুযায়ী sub-agent-এ ভাগ করুন।

Parallel tool calling: একে অপরের ওপর নির্ভরশীল নয় এমন তথ্য (যেমন টোকিওর আবহাওয়া এবং USD→JPY রেট) একই turn-এ একসাথে কল করুন। এটাই tool-heavy এজেন্টের সবচেয়ে বড় latency জয়।

MCP (Model Context Protocol): Anthropic ২০২৪-এর শেষে চালু করা ও এখন OpenAI, Google ও প্রধান IDE vendor-রা গ্রহণ করেছে এমন একটি খোলা মানদণ্ড।[12] model হলো client; data/tool প্রদানকারী চালায় MCP server। server তিনটি primitive প্রকাশ করে:

  • Tools — model যে ফাংশন কল করতে পারে।
  • Resources — শুধু-পড়ার যোগ্য তথ্য (ফাইল, DB row, ওয়েবপেজ)। model লক্ষ্য অনুযায়ী read করার সিদ্ধান্ত নেয়।
  • Prompts — নামকরা prompt টেমপ্লেট যা host তালিকা করে ব্যবহারকারীকে নাম ধরে ব্যবহার করতে দেয়।

MCP-এর গুরুত্ব: MCP-এর আগে প্রতিটি IDE / agent app প্রতিটি data source-এর জন্য কাস্টম integration লিখত। এখন একটি MCP server (যেমন Postgres-এর জন্য) লিখলে সেটা সব MCP-compatible client — Claude Code, Cursor, VS Code, custom agent — ব্যবহার করতে পারে।

Sandboxed code execution: অনেক এজেন্ট কাজ সবচেয়ে সহজে কোড দিয়ে প্রকাশ করা যায় ("কলাম X-এর গড় বের কর")। model-কে sandbox-এ কোড লিখে রান করার অনুমতি দিলে tool-এর বিস্ফোরণ এড়ানো যায় এবং গাণিতিক নির্ভুলতা পাওয়া যায়। ২০২৫-এর প্রধান বিকল্প: E2B (Firecracker microVM, sub-second Python), Modal (hosted container + GPU), Daytona (full dev environment), Cloudflare Workers/Sandbox (edge isolates)।

API wrapper: প্রতিটি internal API-কে এমন একটি ফাংশনে মুড়িয়ে দিন যা (ক) এক বাক্যে purpose বর্ণনা করে, (খ) typed input নেয়, (গ) ফলাফল অথবা {error, retryable} envelope ফেরত দেয়।

Tool result formatting: model আপনার tool-এর output পরের turn-এ prompt-এর অংশ হিসেবে পুনঃপড়ে। তাই output হলো prompt content। তিনটি নিয়ম:[10]

  • নির্মমভাবে ছাঁটাই করুন: ১০,০০০-row SQL ফলাফল context window উড়িয়ে দেবে। শীর্ষ N ফেরত দিন, বাকিটা সারমর্ম করুন।
  • পড়ার জন্য ফর্ম্যাট করুন, সংরক্ষণের জন্য নয়: মানুষের যুক্তির জন্য Markdown table JSON array-এর চেয়ে ভালো।
  • একটি "এটি কী বোঝায়" বাক্য যোগ করুন যখন ফলাফল অ-সুস্পষ্ট — model-এর পুনঃউদ্ভাবন বাঁচায়।
টুলবক্সের উপমা: AI-কে একজন handyperson হিসেবে ভাবুন। তাকে ৩০টি টুলের বাক্স দিচ্ছেন, কিন্তু প্রতিটি টুলের লেবেল অস্পষ্ট হলে ("জিনিসপত্র", "কর্তব্যটা") সে ভুল টুল ধরবে। স্পষ্টভাবে লেবেল করলে ("ফিলিপস স্ক্রুড্রাইভার, সাইজ ২") সঠিক টুল ধরে। MCP হলো টুলের হাতলের স্ট্যান্ডার্ড সাইজ — এখন প্রতিটি টুলবক্স প্রতিটি টুলে খাপায়। সারাংশের নিয়ম: handyperson crawl space থেকে ফিরে আসলে সে সারা junk drawer আপনার রান্নাঘরের টেবিলে ফেলে না দিয়ে সহজ ইংরেজিতে বলে কী পেয়েছে।
