Inference (servers, quantization, providers)

Every LLM call has two sides: the request you send and the inference that serves it. Most teams start by renting (Together, Fireworks, Groq, Cerebras, Replicate, AWS Bedrock). Once usage justifies it, you self-host with vLLM, TGI, SGLang, Ollama, or llama.cpp — and learn a different optimization vocabulary: KV cache, prefix caching, speculative decoding, continuous batching.

Rule of thumb: start hosted. Move to self-hosting once your bill exceeds the cost of a half-time ML engineer plus two H100s.

Inference servers

When you self-host, an inference server is the process that loads model weights into GPU memory and serves requests. The five that matter in 2025:

vLLM

The throughput champion. PagedAttention + continuous batching typically deliver 10–24× the throughput of naive Hugging Face.[13] Python API + OpenAI-compatible HTTP server.

TGI (text-generation-inference)

Hugging Face's Rust+Python server. Polished, supports the HF model hub natively, slightly lower raw TPS than TGI/vLLM.

SGLang

Optimised for structured-output and multi-call programs (RadixAttention for prefix caching across calls).[14]

Ollama

One-line CLI for local laptops and small servers. Best for dev and small-scale prod.

llama.cpp

CPU-first, GGUF-native, runs on phones and Raspberry Pis. Foundation for most edge inference.[15]

TensorRT-LLM / Triton

NVIDIA's compiled kernels for maximum H100 throughput. Most ops effort, best raw TPS.

Quantization: GGUF, AWQ, GPTQ, INT4/INT8

Quantization reduces the precision of model weights from 16-bit to 8- or 4-bit, trading a small amount of quality for 2–4× less GPU memory and proportionally faster inference. The common formats:

  • GGUF — llama.cpp's format. Single file, CPU+GPU hybrid, the de facto standard for open-weight local inference.[15]
  • AWQ — Activation-aware Weight Quantization. 4-bit with near-FP16 quality; popular for vLLM/SGLang.[16]
  • GPTQ — older, still common for GPU serving.
  • INT8 / FP8 — minimal-quality-loss quantisation on H100s; native hardware support.
  • INT4 / NF4 — bitsandbytes (QLora) for training; also used at inference time.
Quantisation trade-off (illustrative, not benchmark-exact). Going from FP16 to AWQ-4bit cuts memory 4× with small quality loss for most workloads.
কোয়ান্টাইজেশন ট্রেড-অফ (চিত্রলিখিত, benchmark-সঠিক নয়)। FP16 থেকে AWQ-4bit-এ গেলে বেশিরভাগ কাজে মানের সামান্য ক্ষতিতে মেমরি ৪× কমে।

KV cache, prefix caching, speculative decoding

Three ideas that show up in every modern inference server:

  • Paged KV cache: instead of one contiguous buffer per request, KV cache memory is allocated in pages (à la OS virtual memory). vLLM's PagedAttention removes the wasted-memory problem of naive serving.[13]
  • Prefix caching: if many requests share a long system prompt, the server hashes the prefix and reuses the cached KV. Anthropic's prompt_caching and OpenAI's cached_prompt save 80–90% of cost on the cached portion.[17]
  • Speculative decoding: a tiny draft model proposes the next 5–10 tokens; the big model verifies them in parallel. Net throughput +2–3× for free, no quality loss.

Continuous batching and throughput tuning

Naive serving processes one request at a time per GPU. Continuous batching (vLLM, TGI, SGLang) interleaves tokens from many requests so the GPU is never idle waiting for one slow request. This alone typically delivers 5–20× higher throughput.[13] Add max_num_seqs, max_model_len, and CUDA-graph capture for the next 2×.

GPU economics, edge inference, on-device models

An H100 rents for $2–$4/hr on the major clouds, ~$30k to buy. At a 70B model, you serve ~30 concurrent requests before latency collapses — about $0.10 per 1k generated tokens fully loaded. Edge inference pushes smaller models onto the user's device (3B–8B on phones via MLX, llama.cpp, or vendor SDKs).[15] The trade-off: zero server cost, but quality and capability are limited.

🏎️Layman's versionplain English, no jargon

Two ways to run an AI: rent it, or own it.

• Renting (OpenAI, Anthropic, Together, Fireworks): you pay per request. No setup, no maintenance. Like taking the bus.
• Owning (vLLM on your own GPU): you buy (or rent) a powerful chip, install the software, and run the AI yourself. Like owning a car.

Start with renting. Switch to owning only when the bus fare is more than a car payment. For most companies, renting stays cheaper for years.

The "engine" matters when you own. If you do own, the inference server is the software that turns user requests into GPU math. The five big names in 2025 are vLLM (fastest for big loads), TGI (easy and from Hugging Face), SGLang (best when you reuse the same prompt a lot), Ollama (one-liner for your laptop), and llama.cpp (runs on phones and Raspberry Pis).

Quantisation = "shrinking the AI without ruining it." A full-size AI model takes 16 GB of memory. Quantise it to 4-bit and it takes 4 GB — losing maybe 1% of quality. For most apps you don't notice. This is why your phone can now run a chat AI offline.

Three magic tricks that make serving fast:

• KV cache — the AI remembers what it already computed instead of redoing the math. Like a calculator that holds the previous answer.
• Prefix caching — if 1,000 users all start with the same system prompt ("You are a customer-service agent for Acme Inc…"), the AI computes that once and reuses it. Saves 80%+ on the cached part.
• Speculative decoding — a tiny draft model guesses the next word, the big model checks. Both run at once. Net speedup 2–3× with zero quality loss.

Latency vs throughput — the eternal trade-off. Latency = how fast one user gets their first word (TTFT). Throughput = how many total users the system can serve at once. Continuous batching is the trick that lets you serve 50 users at once with barely more latency than serving 5. It's the difference between "one customer at a time at the deli counter" and "one big batch of soup."

GPU economics: an H100 chip costs ~$30k to buy, or $2–4/hour to rent. At full tilt it serves ~30 conversations at once. So if you're running millions of conversations, owning is cheaper. If you're running thousands, renting is cheaper.

The bus-vs-car analogy: taking the bus (OpenAI, Anthropic, Together) is cheaper when you're one passenger. Owning a car (self-hosting with vLLM) is cheaper when you're a taxi driver. But the car needs fuel (GPUs), maintenance (an ops engineer), and parking (a server room). Quantisation is like taking the engine apart and removing every fourth piston — the car still drives, just slightly less powerfully. KV caching is like remembering your route home so you don't have to re-look-up every turn.
🇧🇩বাংলা ব্যাখ্যাসহজ ভাষায় বিস্তারিত

দুটি পথ: API-ভিত্তিক inference (Together, Fireworks, Groq, Cerebras, Replicate, OpenAI, Anthropic) অথবা স্ব-হোস্টেড inference (vLLM, TGI, SGLang, Ollama, llama.cpp দিয়ে)। বেশিরভাগ দল আগে host করা API দিয়ে শুরু করে; বিল যথেষ্ট বড় হলে স্ব-হোস্টে যায়। সেই ক্ষেত্রে KV cache, prefix caching, speculative decoding, continuous batching — এই vocabulary শিখতে হয়।

Self-host-এর servers:

  • vLLM — throughput চ্যাম্পিয়ন; PagedAttention + continuous batching সাধারণত ১০–২৪× উচ্চতর throughput দেয়।[13]
  • TGI — Hugging Face-এর Rust+Python server।
  • SGLang — structured-output ও multi-call program-এর জন্য অপ্টিমাইজড; RadixAttention prefix caching।[14]
  • Ollama — লোকাল ল্যাপটপ ও ছোট server-এর জন্য এক-লাইনের CLI।
  • llama.cpp — CPU-first, GGUF-native, ফোন ও Raspberry Pi-তেও চলে।[15]
  • TensorRT-LLM / Triton — NVIDIA-র compiled kernel; সর্বোচ্চ H100 throughput, সবচেয়ে বেশি ops প্রচেষ্টা।

Quantisation: weight precision ১৬-বিট থেকে ৮ বা ৪ বিটে নামানো, যাতে GPU memory ২–৪× কমে এবং inference আনুপাতিকভাবে দ্রুত হয়, সামান্য মান কমে। সাধারণ ফর্ম্যাট:

  • GGUF — llama.cpp-এর ফর্ম্যাট, single file, CPU+GPU hybrid, open-weight লোকাল inference-এর মানদণ্ড।[15]
  • AWQ — ৪-বিটে FP16-এর কাছাকাছি মান; vLLM/SGLang-এ জনপ্রিয়।[16]
  • GPTQ — পুরোনো, GPU serving-এ এখনও প্রচলিত।
  • INT8 / FP8 — H100-এ নেটিভ hardware support সহ সর্বনিম্ন মান-ক্ষতি।
  • INT4 / NF4 — bitsandbytes (QLoRA) প্রশিক্ষণে; inference-এও ব্যবহৃত।

তিনটি মন্ত্র যা প্রতিটি আধুনিক server-এ থাকে:

  • Paged KV cache: প্রতিটি request-এর জন্য একটি contiguous buffer-এর বদলে KV cache memory পেজে (OS virtual memory-র মতো) বরাদ্দ করা হয়।[13]
  • Prefix caching: অনেক request একই দীর্ঘ system prompt শেয়ার করলে server prefix hash করে KV পুনরায় ব্যবহার করে। Anthropic-এর prompt_caching ও OpenAI-র cached_prompt cached অংশে ৮০–৯০% খরচ বাঁচায়।[17]
  • Speculative decoding: একটি ছোট draft model পরবর্তী ৫–১০ token প্রস্তাব করে; বড় model সেগুলো সমান্তরালে যাচাই করে। গুণমান না কমিয়ে throughput ২–৩×।

Continuous batching: naive serving GPU-তে একবারে একটি request প্রক্রিয়া করে। Continuous batching (vLLM, TGI, SGLang) অনেক request-এর token আন্তঃপ্রবিষ্ট করে যাতে একটি slow request-এর জন্য GPU কখনো নিষ্ক্রিয় না হয়। এটাই এককভাবে ৫–২০× বেশি throughput দেয়।[13]

Latency বনাম throughput (TTFT, TPS): TTFT (time to first token) হলো ব্যবহারকারী কত তাড়াতাড়ি প্রথম শব্দ দেখে। TPS (tokens per second, per request) হলো generation-এর গতি যা ব্যবহারকারী দেখে। Aggregate throughput হলো server মোট কত token নিঃসরণ করে। p99 latency হলো সবচেয়ে খারাপ ১%।

GPU economics, edge inference, on-device models: H100 প্রধান cloud-এ ঘণ্টায় $2–$4-এ ভাড়া নেওয়া যায়, কিন্তু কেনা ~$30k। ৭০B মডেলে এটি latency ভেঙে পড়ার আগে প্রায় ৩০ সমকালীন request সার্ভ করে — পুরো লোডে প্রায় $0.10/১k generated token। Edge inference ছোট মডেল (৩B–৮B) ব্যবহারকারীর ডিভাইসে ঠেলে দেয় (MLX, llama.cpp বা vendor SDK দিয়ে)।[15]

Inference providers (২০২৫): Together (open-weight catalogue, ভালো default), Fireworks (দ্রুত, function-calling-optimised), Groq (LPU hardware, ultra-low latency), Cerebras (wafer-scale chip), Replicate (pay-per-second, model marketplace), AWS Bedrock / Azure AI Foundry (enterprise compliance), OpenRouter (aggregator)।

বাস বনাম গাড়ির উপমা: API inference হলো বাসে যাতায়াত (OpenAI, Anthropic, Together)। আপনি একজন যাত্রী হলে সস্তা। স্ব-হোস্ট (vLLM) হলো গাড়ি কেনা। ট্যাক্সি চালক হলে গাড়ি সস্তা, কিন্তু জ্বালানি (GPU), মেইনটেন্যান্স (ops ইঞ্জিনিয়ার) ও পার্কিং (server room) লাগে। কোয়ান্টাইজেশন হলো ইঞ্জিন খুলে প্রতি চতুর্থ পিস্টন বাদ দেওয়া — গাড়ি এখনও চলে, শুধু কম শক্তিতে। KV caching হলো বাড়ি ফেরার রাস্তা মনে রাখা, যাতে প্রতিটি মোড়ে আবার ম্যাপ না দেখতে হয়।
